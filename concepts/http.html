HTTP · step 0 and everything after

One request in, one response out

Every framework in this course is a convenience on top of this picture. A request is a method, a path, some headers and maybe a body. A response is a status, some headers and maybe a body. Send one and look at each part.

1 The whole protocol, in one line

Request GET /products?q=mug HTTP/1.1 Accept: application/json Authorization: Bearer … body: usually empty on GET
over TCP

Response HTTP/1.1 200 OK Content-Type: application/json X-Total-Count: 6 body: [{ … }, { … }]

The status line is not decoration. It is the first thing the client reads, and the only thing some clients read.

3 The status code is a sentence

The number tells the client what kind of thing happened before it reads a single byte of the body.

Four headers worth knowing

Content-Type — what the body is. JSON is application/json. Without it the client guesses, and guesses wrong.

Authorization — the client's proof. In this course: Bearer <token>.

Access-Control-Allow-Origin — the server's permission slip for a browser on another origin. curl never asks.

Cache-Control / X-Cache — whether this answer came from memory. The course makes its own X-Cache.

The body is a stream. Node gives it to you in chunks. Express's express.json() is the middleware that collects the chunks and parses them. Forget it, and req.body is undefined.

4 What the framework actually removed

raw node — step 0 
if (req.method === 'GET' && req.url === '/products') {
  res.writeHead(200, {
    'Content-Type': 'application/json',
  });
  res.end(JSON.stringify(products));
} else {
  res.writeHead(404);
  res.end(JSON.stringify({ error: 'Not found' }));
}
express — step 1 
app.get('/products', (req, res) => {
  res.json(products);
});

app.use((req, res) => {
  res.status(404).json({ error: 'Not found' });
});

Same bytes on the wire. Fewer decisions repeated per route.
