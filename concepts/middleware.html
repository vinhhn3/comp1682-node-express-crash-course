The real order in this project

  1. rateLimit — before anything expensive
  2. cors — before the request is read
  3. express.json — now there is a body
  4. routes — match the path
  5. requireAuth — a route middleware
  6. validate — another route middleware
  7. controller — the work
  8. notFound — only if no route matched
  9. errorHandler — last, four arguments

! Three rules that explain the odd behaviour

1 · Order is registration order

Express runs app.use in the order you wrote it, then the route's own middleware left to right. There is no priority system.

2 · A response stops the queue

If a middleware calls res.json or res.end and does not call next, the handler never runs. That is why auth is cheap and early.

3 · Errors skip to the end

next(err) jumps past every normal middleware, straight to the four-argument handler. Put it last, or it will not catch.

? Why auth before validate

validate → auth an anonymous caller learns your field names and rules, one 400 at a time.
swap
auth → validate an anonymous caller gets 401 and nothing else. A known caller gets useful 400s.

It also saves work: no zod parse for a request that was never allowed in.
