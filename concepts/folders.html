The folder is the responsibility

A file's address answers three questions before anyone opens it: what it does, what it may import, and what it must never know. The tree appears one folder at a time, when the code has the problem the folder solves.

5 Where does this new file go?

The question to ask

  • Does it know a URL? → routes/
  • Does it choose a status code or read req? → controllers/
  • Does it call Model.find? → repositories/
  • Does it describe stored data? → models/
  • Does it run before the handler and maybe stop it? → middlewares/
  • Does it only describe a request body? → schemas/
  • Does it read the environment? → config/
  • Is it a pure helper with no HTTP and no database? → utils/

Three smells to catch in review

A controller that imports Product and writes a query. The repository has been bypassed.
A repository that takes req or returns a status code. It cannot be used by a seed script or a test without faking HTTP.
A route with an inline async (req,res) => {…} body. Now the URL, the rules and the data access live in one line.
A new feature adds a model, a repository method, a controller, a schema and a route — and touches nothing else.
