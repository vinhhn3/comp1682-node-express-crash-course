CORS · step 16

The browser asks permission first

This page is served from localhost:5173. The API is on localhost:8000. Different port, different origin. The browser will send the request, then refuse to hand you the answer unless the response says it may.

Who enforces CORS? The browser, on the response. The server only supplies headers. curl, a mobile app or another server never check them.

? Why curl works and the page does not

    

      

        
Same origin

        
Scheme, host and port all match. The browser does not ask anyone. http://localhost:5173 and http://127.0.0.1:5173 are not the same origin.

      

      

        
Simple request

        
GET, HEAD or POST with a form content type and no custom headers. It goes straight out; the response still needs the header.

      

      

        
Preflighted request

        
application/json, Authorization, PATCH, DELETE. The browser sends OPTIONS first and waits for permission.

      

    

  


  

    
! The three headers that matter

    

      

        
HeaderAnswers

        
Access-Control-Allow-OriginWhich page may read this response? One origin, or *. Not a list.

        
Access-Control-Allow-MethodsWhich verbs the preflight may use.

        
Access-Control-Allow-HeadersWhich request headers the preflight may send. Authorization is not automatic.

        
Access-Control-Allow-CredentialsMay the browser attach cookies? With credentials, * is not allowed as the origin.

      

      

        The course's allowlist lives in CORS_ORIGINS and defaults to
        http://localhost:5173 — the concept tab. An origin that is not on the list
        gets 403 and no allow header.
      

    

  


  

    
⚠ The three mistakes everyone makes

    

      

        
1 · Blaming the server

        
The route logs a 200, the browser shows a failure. The server did its part; the response is missing a header the browser wanted.

      

      

        
2 · Adding the header in the error handler

        
A 500 with no CORS header looks like a network failure in the console. Put cors() early, so even errors carry it.

      

      

        
3 · * with credentials

        
Cookies plus a wildcard origin is refused by the browser. Echo the exact origin and send Vary: Origin.
