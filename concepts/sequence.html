Data flow · twenty-one stories, plain words

Follow the data, not the arrows

A call arrow carries values down; a dashed return carries a result up. The interesting part is not who calls whom. It is what the value looks like when it arrives, and what each layer is allowed to do with it.

→ What travels at each hop

Plain words, no method names. The shapes are the lesson: a controller that passes a database document upward leaks the database into HTTP.

! Four shapes, in order

HTTP shapes

req.params, req.query, req.body, req.user. Strings from URLs, parsed JSON, a verified token claim. They exist only at the edge and they are the controller's problem.

Plain values

What the controller passes to the repository: { q: "mug" }, { title, price }. No req, no status codes. This is the shape that makes a repository callable from anywhere.

Documents

Mongoose documents with getters, _id and timestamps. They belong to the repository and below. The controller may read fields; it must not build queries.

JSON

The toJSON transform maps _id → id, drops __v, and hides password. One place decides what the client ever sees.
